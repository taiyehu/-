# 联机 Demo

在项目根目录运行：

```powershell
cd demo
node server.js
```

打开 `http://localhost:3000`。本机测试时，输入测试种子并点击“创建四标签测试房间”，再从裁判页分别点击“打开 A/B/C 队标签页”。四个标签页各有独立身份；刷新后身份仍保留。裁判点击“重置本房间”会清空分数、位置、牌库进度和战斗记录，但保留房间码及四个标签页的身份；相同测试种子会复现相同牌序。若要用三台设备正式加入，点击“创建普通房间”，再让三队输入房间码。其他设备访问时使用运行服务器的电脑局域网地址，例如 `http://192.168.1.10:3000`。运行 `node --test` 可检查核心规则。

裁判创建房间时设置初始金钱和初始收入；三队初始积分固定为 0。三个大建筑随机且不重复地分配给三队作为起点。测试房间用相同种子重置后，起点与牌序会复现。每队进入新回合时显示“第 x 回合”过场。鼠标悬停手牌可放大预览；点击后显示整张牌，选择“打出”才进入后续操作。选牌移动时，地图会高亮所有可到达终点；点击终点会提交移动，队伍图标依次经过路线上的节点。每轮按“移动及格子效果 → 战斗判定 → 房屋手牌使用或跳过 → 结束回合”的顺序进行。房间数据暂存在服务器内存；重启服务器会清空房间。

正式牌面数据在 `../cards/hand.csv`、`../cards/events.csv`、`../cards/misfortunes.csv`，沿用卡牌生成器的列，额外加入 `effect_type`、`effect_value` 和 `quantity` 供 demo 识别。当前每队使用 7 张已制作的手牌，起手 6 张。修改 CSV 和对应成品图片后需要重启服务器。问号牌移动时由服务器掷 d6；在房屋使用时也由服务器掷 d6，获得相应积分、点数 × 70 金钱及一次事件抵消。其他卡牌在适用房屋支付费用后，由裁判根据牌面音游条件判定成功或失败；成功时结算卡面效果。言而无信的额外移动需再打出一张手牌，不触发格子与战斗；机械帮手的弃牌能力在房屋内无可用手牌时每回合可用一次。

地图对所有队伍完整显示，左上角列出其他队伍的当前回合数。队伍视角中，若另一队已领先，地图显示其在本队当前回合的终点；若另一队尚未完成本队当前回合，地图显示其轻度虚化的实时位置，悬停图标可查看实际回合数。裁判仍看所有队伍的实时位置。战斗表按队伍的当前回合和记录到达时间过滤，裁判显示全量。Arcaea 支线按地图箭头为 `R12 → A2 → Arcaea → A1 → R1`。收入格经过时获得当前收入、停留时获得双倍；收税格经过扣 20、停留扣 40，余额最低为 0，金钱变化会在计分板浮动显示。停在事件格会播放“触发事件”并展示事件卡；经过厄运 B 或停在 B 会播放“触发厄运”并展示抽到的厄运卡。目前已制作的厄运只有“社长造访”，触发时立即让三队竞标，不等待回合数同步；三队出价后各自支付出价，最低出价队扣 2 分；最低价并列时并列队伍均扣 2 分。

目前 CSV 中仅有一张事件卡和一张厄运卡；规则书中的其他事件及厄运牌、终局判定仍未接入。裁判可手动调分，同轮同格战斗可手动选择胜者。厄运 B 的双向通路是当前 demo 的临时设定，正式玩法需要确认方向。普通房间的席位只能加入一次；四标签测试房间的裁判链接可重复打开席位。
